# MediaShelf v0.1.5

## 设置页能直接测凭据了

「测试连接」按钮以前只创建了对象、没加进布局，所以从来不可见。现在它在凭据输入框正下方，填完点一下就能看到结果：

```
✓ 连接正常，示例结果：阿凡达（2009）
✗ 401 API Key 无效
✗ 连接超时，检查网络或代理
```

请求走后台线程，不冻结对话框。改了凭据会把上一次的结果作废，避免"显示可用但其实是旧 Key"。

## 主界面能看到 TMDB 连接状态

工具栏「设置」左边多了一个状态徽标，颜色即时反映真实状态：

| 显示 | 含义 |
|---|---|
| ● TMDB 已连接（绿） | 凭据验证通过 |
| ● TMDB 不可用（红） | 验证失败，鼠标悬停看具体原因 |
| ● TMDB 未配置（灰） | 没有凭据，会退回 Wikidata |
| ● TMDB 验证中（黄） | 正在后台连接 |

点徽标直接打开设置。

## 空目录一键清理

整理完整的库一定留下两样东西：搬空的旧文件夹、带 `_空壳待删` 标记的历史遗留。以前只能去 DSM 里手动删，现在：

- **执行完自动清**：一批操作成功后自动扫库，删掉所有"整棵树里没有任何视频"的目录，日志报告数量。
- **主界面「清理空目录」**：随时手动跑，弹出清单勾选确认，带残留文件的目录会标出文件和大小。

判定规则只有一条：**含视频的目录永远不进列表**。名字带 `_空壳待删` 但里面真有 mkv 的，判为跳过而不是删除。

顺带解决了上一版遗留的问题：`夺宝奇兵（系列） Collection` 和 `海扁王（系列） Collection` 当时因 `WinError 5` 改不了名，这次查明它们本来就是空目录，直接删掉了。

## 删除为什么以前一直失败

上一版判断是"NAS 没有回收站"，只对了一半。真正的原因：宿主安全层接管了 Python 进程内的 `os.rmdir` / `shutil.rmtree`，强制改写成"移到回收站"；SMB 盘上没有回收站，于是必然失败，报的却是 `WinError 145 目录不是空的`——错误码完全误导。

现在直接调 Win32 `RemoveDirectoryW` / `DeleteFileW`，不经过 Python 的删除封装，也不拉子进程。实测在你的库上删掉 19 个空目录，0 失败，53 部视频一个没动。
