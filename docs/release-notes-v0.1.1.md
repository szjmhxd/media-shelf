## MediaShelf v0.1.1

这一版全是在修 v0.1.0 的实际缺陷。如果你点「联网识别」后表格一片空白、点「预览并执行」弹出「没有可执行的操作」，问题都在这版修掉了。

### 修掉的五个 bug

**1. 识别线程会因为一条出错而整个静默退出。**
识别线程只捕获 TMDB 的异常类型，而免 Key 数据源抛的是另一种异常。第一条片子请求出问题，整个线程就直接死掉——界面看起来像「什么都没发生」，剩下的片子永远停在「待识别」。现在每条独立兜底，一条失败不影响其余，且状态列会写明失败原因（网络错误 / 被限流 / 无匹配）。

**2. 没有元数据时完全不能改名。**
生成操作计划时要求每部片子都有中英文名，而免 Key 数据源基本填不出来，于是计划为空、弹「没有可执行的操作」。这是 v0.1.0 最严重的设计错误：**改名本来就不需要联网**。现在片名和年份从文件名就地解析，一部都没识别也能把库整理成 `片名 (年份)/片名 (年份).mkv`，只有 nfo 和海报需要元数据。

**3. 片名以年份开头的会被解析成空。**
`2012 (2009).mkv` 的片名被当成年份、年份被当成片名，最后搜了个空字符串。现在优先取末尾括号里的年份。

**4. 50 GB 以上的 remux 探测超时。**
ffprobe 默认会把大文件从头分析很久，网络盘上 60 秒不够，报「ffprobe 调用失败」，这三部片子连带被取消勾选。加上 `-analyzeduration 20M -probesize 20M` 后只读文件头和少量样本，57 GB 的片子 4 秒读完。

**5. 空搜索结果被永久缓存。**
一次网络抖动导致查不到，这个「查不到」就被写进磁盘缓存，之后永远查不到。现在空结果不写缓存，缓存键带版本号前缀。

### 免 Key 数据源换成 Wikidata

原来的维基百科全文搜索对中文片名几乎不可用——搜「不要见怪」返回的是「謝苗」「薛之谦」。换成 Wikidata 按标签和别名搜索，能直接拿到简体中文名、英文名、上映年份和 IMDb ID，命中率从基本为零提升到大约三成。

**但它仍然是兜底方案。** Wikidata 的中文标签覆盖率不足：`冰海陷落` 只有港译《潛艦獵殺令》，`不要见怪` 只有《調教你處男》，标题对不上就只能放弃。而且 Wikimedia 对连续请求有速率限制，批量识别会遇到 429（界面上会写「被限流，稍后再试」）。

要正经整理整库，还是去 themoviedb.org 申请免费 API Key，填进「设置」。那是为影视数据设计的接口，命中率是另一个量级。

### 其他改进

- 匹配阈值收紧：宁可空着也不填错。《冲出地球》被错配成《熊出没·重返地球》这类问题不会再出现
- 识别进行中不允许叠加扫描或执行，避免基于半截数据生成计划
- 一部都没匹配上时直接弹窗说明原因和解决办法，不再让人对着空表格猜
- 失败重跑不会清空已填好的中英文名
- 中文维基条目名里的 `(電影)`、`(2021年电影)` 等消歧后缀会被去掉

### 升级建议

直接换成这个版本。如果你已经用 v0.1.0 跑过识别，`%APPDATA%\MediaShelf\data\` 下的旧缓存可以删掉，缓存键已加版本前缀，旧数据不会再生效。
